# TLA+ models

TLA+ specifications for lia, checked with TLC, together with the scripts and Bun drivers that check them. CI runs the MCP models on `main` and on pull requests that change the code they cover, as `scripts/detect-ci-need.sh` decides; the `lia mcp call` model on `main` and on pull requests labeled `ci:tla-mcp-call`; and the recovery, gateway_open, and agent_runtime models, each with its driver, on every pull request. Run the others when you change the behavior they describe.

## Requirements

Java 11 or later and `tla2tools.jar`:

```sh
brew install openjdk
mkdir -p ~/.local/share/tla
curl -fL -o ~/.local/share/tla/tla2tools.jar \
  https://github.com/tlaplus/tlaplus/releases/latest/download/tla2tools.jar
```

Set `TLA2TOOLS_JAR` to use a jar in another location. The scripts look for Java in `JAVA_HOME`, then in Homebrew's OpenJDK, then on `PATH`. The `mcp/` and `session_manager/` runners also need Python 3.

The drivers need Bun. Most of them also run the binary that `zig build` puts in `zig-out/bin/lia`. They take these settings from the environment:

| Variable | Default | Effect |
|---|---|---|
| `LIA_BIN` | `zig-out/bin/lia` | The binary under test |
| `LIA_WORKTREE` | this checkout | The checkout whose binary and `tests/e2e/` helpers a driver uses |
| `LIA_TLA_OUT` | a folder under the system temp folder | Where traces, TLC logs, and reports go |
| `LIA_SOUND` | `0` in every driver | Keep it at `0`; sound playback can overload a machine during a run |

## MCP in CI

CI's `TLA+ MCP models and drivers` job runs each engine model's smoke config (`mcp/run.py check`), `mcp_host/check.sh`, and both MCP drivers, on `main` and on pull requests that change MCP code, these models, their drivers, or the files the drivers load. The engine models' planted bugs (`mcp/check.sh`) run only by hand: they measure the checks, not the code.

`.github/workflows/tla-mcp-call.yml` runs `mcp_call/check.sh`, planted bugs included, on every push to `main` and on pull requests labeled `ci:tla-mcp-call`.

## MCP models without a driver here

The engine models of the two HTTP transports, input-required rounds, authorization, subscriptions, and elicitation are model-checked only. Their traces came from a conformance adapter that is not part of lia. The `drivers/mcp_host/` sign-in tests drive real lia over HTTP against the fake server in `drivers/mcp/fakes/`.

The `shell_command/` tests also check a proposed design. Those checks run only with `LIA_TLA_PROPOSED=1`, and they fail until lia implements the design.

A `check.sh` that uses `lib/tlc.sh` takes config names to run only those, for example `tests/tla/usage/check.sh LeanUsage`. `Fork`, `V1Conversion`, and the full `LeanUsage` config can run for many minutes. `session_manager/README.md` describes each session spec, the planted bugs, and the trace checkers.
